# Results analysis

All analysis is scripted and re-runnable: `make analysis` (or `python3 analysis/make_all.py`) must regenerate
every table in `report/generated/` and every figure in `report/figures/` from `results/raw/` alone.
**No number is typed by hand into the report.**

## Environment
```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt      # numpy, pandas, matplotlib (+ scipy where needed)
pip freeze > requirements-lock.txt   # exact versions for reproducibility
```

## Provided scripts (`.claude/skills/results-analysis/scripts/`)
| Script | Purpose |
|---|---|
| `summarize.py` | per-configuration median, Q1, Q3, IQR, min, max, mean, std, k (count), peak RSS, failure counts; `--limits` gives the largest completed n and smallest failed n; `--latex` writes a booktabs table |
| `growth_fit.py` | log-log fit `T ≈ c·n^b` per method with 95% CI of b → compare with b = 3 |
| `speedup.py` | `S(p) = T_seq/T_p` and `E(p) = S/p` from medians of RAW data, bootstrap 95% CI; refuses to mix timer boundaries |
| `plot_style.py` | IEEE-sized figures, Okabe–Ito colour-blind palette, consistent colour per method, `plot_median_iqr`, `savefig` (PDF+PNG) |

Copy or import them from `analysis/` (e.g. `sys.path.insert(0, ".claude/skills/results-analysis/scripts")`).
If you modify them for this assignment, copy them into `analysis/` first so the submission is self-contained.

## Required outputs for every assignment
1. `results/summary/summary.csv` and `results/summary/limits.csv`.
2. A runtime table (median, IQR, k) for **every tested configuration** (main text or appendix).
3. A runtime-vs-n figure (log-log axes, base-2 x axis when n doubles), median markers with IQR error bars,
   one series per method, failures noted in caption/text (e.g. "Python timed out at n = 2048 (600 s limit)").
4. A memory figure or table that names the metric (e.g. "peak RSS via GNU time") — never mix metrics on one axis.
5. A "Limits" table: largest completed n vs largest attempted n per method, with failure type and budget.
6. `report/generated/numbers.tex` with `\newcommand` macros for every key number quoted in the text, generated by
   the analysis script, e.g. `\newcommand{\ExpC}{2.98}` → used as "an empirical exponent of \ExpC{}".

## Assignment-specific analyses
- **A1**: growth exponent per language (fit over the n range where the trend is stable; state the range);
  time per multiply-add `T/n³` in ns vs n (reveals cache transitions); ratios between languages *at the same n*
  with the caveat that they are scoped to this machine/settings.
- **A2**: speedup of each optimisation over the baseline at each n (same boundary); sparse vs dense time and
  memory vs density at fixed n; nnz(A), nnz(B), nnz(C) and output density; conversion cost reported separately.
- **A3**: runtime vs threads, S(p) and E(p) vs p with ideal line, 1-thread parallel overhead `T_par(1)/T_seq`,
  separate markers for p > physical cores (6 on the reference laptop: Hyper-Threading) and p > logical (oversubscription).
  Vectorisation (optional) analysed at fixed p.
- **A4**: strong scaling (fixed n, workers ↑), S and E vs workers, breakdown of setup/transfer/compute/collect
  where measurable (stacked bars ONLY if the phases do not overlap; otherwise separate bars + explanation),
  comparison to sequential and parallel versions at common n.

## Figure rules (course requirement: label axes and units, name configurations, explain each figure)
- Axis labels with units: `Matrix size n`, `Median runtime [s]`, `Peak RSS [MiB]`, `Speedup S(p)`.
- Caption states: what is plotted, statistic (median, IQR bars), k repetitions, machine, timer boundary.
- Use log scales when values span > 2 orders of magnitude; say so in the caption.
- Width: `column` (3.5 in) for single-column, `text` (7.16 in) only for wide `figure*`.
- No chart junk, no 3D, no titles inside the plot (the caption is the title). Legends must not hide data.
- Load the `dataviz` skill if available for deeper chart guidance.

## Statistical honesty
- Report median + IQR (+ k). Mention when IQR is large relative to the median and investigate (thermal, GC, OS noise).
- Exclusions only by a rule written in the analysis script and stated in the report (e.g. "runs with
  loadavg_1m > 2 excluded; 3 of 420 rows").
- Do not over-interpret differences smaller than the variability. Do not extrapolate beyond tested sizes
  without labelling it as a model prediction.
