# Scientific report (LaTeX → PDF)

Inputs you rely on: `context/report_requirements.md` (mandatory structure + rubric), `context/assignment_brief.md`
(what this assignment must contain), `docs/experiment_plan.md`, `results/summary/*`, `report/generated/*`,
`report/figures/*`.

## Files
- `report/main.tex` — already instantiated from `templates/main.tex` (title and assignment number to fill).
- `report/references.bib` — ONLY verified entries you cite. Start from `templates/references_candidates.bib`.
- `report/generated/` — tables/macros produced by analysis scripts (never edit by hand).
- `report/figures/` — PDF figures produced by analysis scripts.
- Build: `cd report && latexmk -pdf -interaction=nonstopmode main.tex`; final file copied to
  `deliverables/AssignmentNN_RodriguezAlonso_Report.pdf`.

## Mandatory structure (from the course; keep these headings)
1. **Title + abstract** (≈150–200 words): question, method, main quantitative result *with variability*, scope.
   Title page shows name, assignment number, research title (the template does this).
2. **Introduction and Objective**: motivation, one focused research question (RQ), labelled hypotheses (H1…).
3. **Background and Related Work**: algorithms/techniques needed, each claim backed by a verified citation.
4. **Methodology**: implementations, inputs, environment table, correctness checks, measurement protocol, budgets.
5. **Results**: observations only — tables/figures with units, k repetitions and variability; failures as results.
6. **Discussion**: explicit answer to the RQ, hypothesis verdicts, evidence-backed explanations, limitations.
7. **Conclusions**: what is established *within the tested scope*, what remains unresolved.
8. **References and materials**: IEEE references + "Reproducibility Materials" (repo URL, commit/tag, archive
   contents, one-line reproduce command) + "Use of Generative AI" statement.

Target length: **5–8 pages** in IEEE two-column, plus an optional appendix with full tables. Concise but enough to
reproduce the experiment.

## Writing style
- Formal scientific English, mostly active voice in first person singular is acceptable ("I measured…") or
  impersonal ("The study measures…"); choose one and keep it consistent.
- Present tense for what the paper shows, past tense for what was done.
- Precise and scoped: "On the i7-9750H laptop, with gcc -O2, the C implementation was X times faster than …
  for n ≤ 1024", never "C is faster than Java".
- Separate clearly: **hypothesis/prediction** (Introduction) → **observation** (Results) → **interpretation**
  (Discussion). Mark conjectures ("a plausible explanation, not verified here, is …").
- Numbers: SI units with `\SI{}`/`\si{}` or plain "1.23 s"; consistent significant digits (3 s.f. typical);
  always with k and the variability statistic (median [IQR]).
- Every figure and table referenced in the text (`\cref{fig:...}`), captions self-contained.
- Abbreviations defined at first use (RQ, IQR, RSS, JIT, CSR, …).
- No marketing language, no filler, no unsupported superlatives.

## Numbers must be traceable
- Quote key numbers through macros in `report/generated/numbers.tex` generated by the analysis code.
- Tables via `\input{generated/...}`. Figures from `report/figures/` generated by scripts.
- Before finishing, grep the .tex for literal numbers in Results/Discussion and confirm each matches the CSVs.

## References (IEEE style via `IEEEtran.bst`)
- Use `references_candidates.bib` as a starting list — **verify every entry with WebSearch/WebFetch** (DOI resolver,
  publisher page or dblp): authors, title, venue, year, pages; add the DOI you verified.
- Confirm that the source supports the exact claim. If you cannot verify a reference, do not cite it.
- Add official documentation (OpenMP spec, JMH, Python `tracemalloc`, Spark/Dask docs…) as `@misc` with URL and
  access date when you rely on them.
- Typical count: 8–15 references. Cite earlier own assignments as `@misc` with repository URL + commit.

## Generative AI disclosure (mandatory by course policy)
Draft an accurate statement naming the tool (Claude Code by Anthropic, with the model name shown in the session),
the purpose (e.g. planning, code drafting/debugging, analysis scripts, LaTeX drafting, language revision) and the
affected parts. State that Daniel reviewed and ran the code, that all measurements come from his own runs and that
he verified every reference. **Ask Daniel to confirm the wording** — he must be able to defend it.

## Compile and check
```bash
cd report && latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
grep -nE "^!|undefined|Overfull" main.log | head     # fix errors, undefined refs/citations, big overfull boxes
pdftoppm -r 70 -png main.pdf /tmp/page                 # look at the pages (Read the PNGs) to check layout
```
If a LaTeX package is missing (TinyTeX):
`tlmgr --repository https://ftp.math.utah.edu/pub/tex/historic/systems/texlive/2025/tlnet-final install <pkg>`

Then run the `report-review` skill before declaring the report finished.
